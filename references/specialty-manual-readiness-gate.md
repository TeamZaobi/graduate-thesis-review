# 专项手册完备性 Gate

每次论文进入专业路由后，不要立刻假设现有专项手册已经足够。先用这份 gate 判断：当前专项手册对“这篇论文、这个研究类型、这个毕业论文阶段”到底是 `complete`、`partial` 还是 `missing`。

这一步的目标不是拖慢审查，而是避免两类高成本错误：

1. 手册不够用，却直接按“已覆盖”进入深审
2. 单篇论文的偶然特征，反向污染共享专项手册

路径说明：

1. 当前 canonical 机器锚点是 `notes/legacy-review-manifest.json.specialty_gate`
2. 当前 canonical 人类记录是 `notes/专业手册完备性判断.md`
3. `reviews/` 下的同名路径当前视作兼容 alias

## 1. 什么时候必须过这个 gate

以下任一情况满足，都必须先做完备性判断：

- 论文首次进入某个专业专项
- 论文跨两个专业或跨两个研究类型
- 用户明确要求“严格把关”“高标准送审/答辩”“按最新规范”
- 现有专项文件创建较早、最近没有更新，或明显只覆盖一种亚型论文
- 论文包含专项文件里未覆盖的关键对象：新型干预、特殊结局、复杂设备、领域特定规范、学校送审场景
- 需要新增或重写专业手册

## 2. 先识别六个维度

在判断手册是否完备前，先把论文画像压缩成六个维度：

1. 专业：大学科 + 小学科
2. 研究类型：`RCT / 观察性 / 诊断 / 预测 / 综述 / 纯工程`
3. 论文阶段：`开题 / 中期 / 送审前 / 外审回复 / 预答辩 / 正式答辩前 / 终稿回归`
4. 证据主轴：`正文文本 / 表格 / 图像 / 补充材料 / 原始数据或结果导出`
5. 学科语域：该学科导师、学生和外审最自然接受的审查用语
6. 多领域闭环：是否同时需要 `流行病学/研究设计`、`生物统计`、`具体临床领域` 或 `工程/设备` 独立发言

没有先把这六个维度说清，就不要下“手册足够/不够”的结论。

## 3. 完备性检查项

按下面十一项逐条判断。不要只看“有没有这个文件”，要看它是否真的能支撑当前论文。

### A. 元信息是否完整

- 是否有 `最后更新 / 适用范围 / 主要参考规范`
- 适用范围是否写清到足以区分相邻亚专业

### B. 专业覆盖是否匹配

- 当前论文的主专业、亚专业，是否落在手册的适用边界里
- 是否误把相邻专业的经验稿当成当前专业的标准

### C. 研究类型是否有分流

- 当前论文属于哪种研究类型
- 手册是否写清这一类型在本专业下该怎么审

### D. 毕业论文阶段是否覆盖

- 这篇论文当前是在开题、送审、外审回复还是答辩前精修
- 手册是否写清该阶段应该优先抓什么，而不是只给通用学术检查

### E. 核心结局和金标准是否覆盖

- 手册是否能回答：本专业的核心结局是什么、哪些是替代指标、哪些是金标准或最低可信测量

### F. 高频风险是否可直接分级

- 是否有能直接映射到 `P0 / P1 / P2` 的本专业高频问题
- 是否能给出安全降级表述，而不是只会提示“有风险”

### G. 与通用框架和其他专项的冲突是否已写清

- 是否写清哪些通用检查应保留、哪些应屏蔽、冲突时谁优先

### H. 来源是否足够稳

- 是否主要建立在正式规范、一手来源、领域共识，而不是单篇论文经验或某位导师口径

### I. 当前论文的特有缺口是否已显现

- 即使手册整体存在，只要当前论文暴露出它没覆盖的关键问题，也要判为不完备或部分完备

### J. 学科语域是否覆盖

- 手册是否写清本学科常用审查用语，而不是默认沿用软件工程或项目管理隐喻
- 是否能回答“当前学科里哪些词自然，哪些词会显得外行或不专业”
- 对外成品里需要出现的文件名、页面标题、问题标签，是否已有学科内可接受的表达

### K. 是否足以支撑多专家独立审计

- 当前论文如果同时命中 `流行病学 / 生物统计 / 临床领域 / 工程设备` 两条以上闭环，手册是否写清谁主导、谁补约束
- 是否能支持把不同闭环拆开独立审计，而不是只给一套混合口径
- 如果当前没有对应闭环手册，是否已经明确要靠论文级专项补充临时补齐

## 4. 三档结论

### `complete`

满足以下条件时可判为 `complete`：

- 专业和研究类型都匹配
- 手册有元信息、边界、研究类型分流和本专业高频风险
- 能直接支撑当前论文阶段的主要决策
- 没有暴露出阻断深审的关键缺口

允许存在轻微缺口，但不能影响本轮主要判断。

### `partial`

满足以下任一情况，判为 `partial`：

- 手册存在，但只覆盖本专业的一部分亚型论文
- 研究类型分流不够，当前论文需要人工补规则
- 没有毕业论文阶段 guidance，只能做领域方法学检查
- 能做快筛，但不足以支撑高标准深审、逐条改稿或送审/答辩判断
- 当前论文暴露出 1-3 个关键缺口，可以通过本论文专项补充弥补

### `missing`

满足以下任一情况，判为 `missing`：

- 没有对应专项文件
- 有文件，但专业边界明显不匹配
- 文件本质上只是经验备忘，不足以支持可靠审查
- 关键规范、核心结局、研究类型或本论文场景都没有覆盖

## 5. 产出物

只要做了这个 gate，就建议留下最少两类产物。

### 必交付

- `notes/专业手册完备性判断.md`
- `notes/legacy-review-manifest.json.specialty_gate`

建议至少记录：

- 当前论文画像：专业、研究类型、论文阶段
- `domain_stack / primary_loop / supporting_loops`
- 当前论文语域：本学科常用审查用语、应避免的跨学科行话
- 命中的专项文件
- 完备性结论：`complete / partial / missing`
- `discipline_register_status`：`complete / partial / missing`
- `independent_audit_required`：`yes / no`
- `required_expert_checks`：本轮至少需要哪些专家切面
- 结论依据：命中的检查项和缺口
- 下一动作：直接深审，还是先补专项

其中：

- `legacy-review-manifest.json.specialty_gate` 负责机器可读 gate
- `专业手册完备性判断.md` 负责人类可读判断记录和论证过程
- 如果 manifest 仍是占位，可以短暂回退读取 Markdown，但回合内应尽快同步回 manifest

### 条件性交付

当结论是 `partial` 或 `missing` 时，再补：

- `notes/专业专项补充说明.md`

建议至少记录：

- 本论文当前缺的是什么
- 临时补充的规则来自哪里
- 本学科推荐用语、建议替换词和应避免的跨学科行话
- 缺失闭环由谁临时承担，例如“临床闭环先由论文级专项补充承担”
- 哪些仅适用于本论文，不得直接升级为共享专项
- 哪些内容满足升级条件，可在回合结束后提升为共享手册

## 6. `partial` 时怎么补

`partial` 不是“继续硬审”，而是“先补最低可用专项层”。

固定做五件事：

1. 用通用框架继续做快筛，不停工
2. 列出当前手册覆盖不到、但本论文必须回答的问题
3. 查正式规范、一手来源或该领域高质量方法学材料
4. 形成“本论文专项补充”，只补本轮真正需要的规则
5. 标记哪些是 `paper-specific supplement`，哪些可以回灌到共享手册

优先补：

- 核心结局与金标准
- 当前研究类型的最低方法学 gate
- 本论文阶段最常被问的送审/答辩问题
- 高风险安全降级词
- 本学科常用审查用语与替换词
- 多领域闭环之间的主从关系和冲突裁定规则

## 7. `missing` 时怎么补

`missing` 时，不要等待完整手册写完再开始全部工作。按两段走：

### 第一段：不停审

- 用 `clinical-study-types.md + review-rubric.md` 做通用快筛
- 抓明显 `P0 / P1`
- 同时冻结审阅对象、版本真源、图表和补充材料入口

### 第二段：补专项

- 用正式规范和一手来源建立本论文专项补充
- 如果内容具备可复用性，再升级为共享 `specialty-*.md`
- 共享手册升级后，再决定是否回跑第二阶段深审

## 8. 什么时候允许把本论文补充升级为共享专项

以下条件同时满足时，才允许升级：

- 规则不是该论文独有的偶然问题
- 来源稳定，至少能指向正式规范、领域共识或一手方法学依据
- 结论不会误伤相邻亚专业
- 预计后续同类论文仍会反复命中
- 已写清适用边界和不适用边界

如果只是某篇论文的导师偏好、院校格式要求或单个病种细节，不要直接写回共享专项。

## 9. 红线

- 不要把 `paper-specific supplement` 伪装成“领域通用规范”
- 不要因为已有专项文件，就跳过完备性判断
- 不要把“专项文件存在”误判为“专项手册已经足够”
- 不要把学校格式规范、导师偏好和领域方法学规范混在同一层
- 不要把软件工程或数据工程的隐喻直接当成其他学科的成品语域
- 不要因为时间紧，就用不匹配的专业手册硬套整篇论文

## 10. 建议配套动作

- 新建或修改专项文件后，运行 `scripts/check_specialty_manual.py`
- 在回归样例里至少补一条 `partial` 和一条 `missing` 场景
- 如果这轮补过专项，再在最终交付前回看：当前共享手册是否真的被提升，而不是只多了临时文件
