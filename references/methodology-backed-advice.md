# 方法论支撑的建设性建议框架

当任务不只要求“指出问题”，还要求“告诉学生具体怎么改”时，加载此文件，并与下列文件联动：

- [mentor-constructive-layers.md](./mentor-constructive-layers.md)
- [epi-biostat-language-contract.md](./epi-biostat-language-contract.md)
- [mentor-projection-contract.md](./mentor-projection-contract.md)
- [frontier-innovation-gates.md](./frontier-innovation-gates.md)（当命中创新/前沿问题时）

建设性建议不是把批评换成更温和的措辞，而是把**问题类型 -> 修复类型 -> 方法学依据 -> 最小动作 -> 验证动作**串成一个可执行链条。

## 1. 何时必须加载

以下任一条件满足时，不能只靠常规改稿卡：

- 用户明确要求“建设性修改建议”“怎么改”“执行清单”“导师式精修”“可直接替换”
- 任务已经进入 `output.advisor.line-editing` 或 `output.student.execution-pack`
- 问题命中 `证据-结论匹配度`、机制宣称、因果强度、对照可信度、图表证据口径、关键引文支撑
- 用户不只是要“降级表述”，还要知道“为什么这么改、改到哪一步算合格”

## 2. 核心原则

1. **先判可修复性，再判改法**
   先回答“这个问题能不能靠写作修复”，再回答“具体怎么写”。
2. **每条建议必须绑定方法学依据**
   依据可以来自研究类型规则、专项手册、统计闭环、证据-结论匹配度判断、报告规范或引文法证。
3. **最小充分动作优先**
   能靠降级词、补局限性、重排证据顺序解决的，不要默认升级成章节重写。
4. **设计缺陷不伪装成写作问题**
   缺随机隐藏、缺盲法、缺关键对照、缺主要结局依据时，不要用“建议这样表述”掩盖设计硬伤。
5. **每条建议都要有验收标准**
   改完后要能回答：哪一句变了、哪个证据锚点对齐了、哪项风险被降到什么强度。
6. **先过流调/生统语言，再进专业语境**
   导师建议先说明研究设计与估计边界，再进入专病或设备语境。
7. **建设性建议必须分层**
   低工作量修复、高工作量结构修复和前沿升级不能混成一个清单。

## 3. 固定五步法

### 第一步：问题归类

先把问题放进以下一类，不要混写：

- `结论强度过高`
- `证据锚点缺口`
- `方法设计硬伤`
- `报告规范缺漏`
- `结构/章节错位`
- `图表/表格口径不一致`
- `引文支撑不足`
- `术语与语义不稳`

### 第二步：判定修复类型

固定只用以下几类：

- `强度降级`
  - 用于把“证明/证实/优效/机制成立”降回证据能承受的层级
- `局限性补写`
  - 用于诚实暴露样本量、时间窗、测量代理、对照不足、残余混杂等边界
- `证据重锚`
  - 用于把句子重新绑定到表、图、统计输出、方法设定或附录，而不是继续悬空表述
- `结构重排`
  - 用于把目的、方法、结果、结论或讨论内部顺序重新闭合
- `图表/表格回归`
  - 用于修正图题、图注、表述口径、互引关系和关键视觉标记
- `引文升级`
  - 用于把二手文献、综述或弱引替换为指南、一手方法学来源或更贴题文献
- `范围收紧`
  - 用于把普适化、机制化或因果化结论收回到样本、时间窗和研究场景内
- `不可由写作修复`
  - 用于设计、数据、统计或证据本体缺失，必须停笔并转人工回查或补材料

### 第三步：绑定方法学依据

每条建议至少写明一个依据来源：

- `研究类型规则`
- `专项手册`
- `统计/流行病学闭环`
- `证据-结论匹配度`
- `图表法证`
- `引文法证`
- `报告规范`

没有依据来源的“建议这样写更好”，默认不算建设性建议。

### 第四步：限定最小动作

把动作收敛到一个最小单元：

- `句子级`
- `段落级`
- `图题/表题级`
- `图注/表注级`
- `小节级`
- `补充材料级`
- `不可执行，需先补证据`

### 第五步：补验证动作

每条建议至少配一个验证动作：

- 回查对应表图统计量
- 复核摘要/方法/结果/结论是否重新一致
- 复核图号、表号、caption 和正文互引
- 复核引文与论断是否重新匹配
- 复核局限性是否已显式暴露

## 4. 方法学修复路径表

进入建设性建议阶段后，先产一份 `方法学修复路径表.md` 或等价结构，再去写最终改稿卡或学生执行清单。

每条路径最少字段：

- `定位`
- `风险级别`
- `问题归类`
- `修复类型`
- `方法学依据`
- `epi_basis`
- `stats_basis`
- `claim_boundary`
- `当前层级`
- `最小动作`
- `是否可仅靠写作修复`
- `是否需人工回查`
- `是否需要外部知识检索`
- `验证动作`
- `下游产物`

`下游产物` 只允许写：

- `逐条修改建议卡`
- `学生执行项`
- `答辩口径`
- `退回评审，不进入改写`

## 5. 从修复路径到下游产物

### 导师式逐条改稿

只有当问题被判定为：

- `强度降级`
- `局限性补写`
- `证据重锚`
- `结构重排`
- `图表/表格回归`
- `引文升级`
- `范围收紧`

才进入逐条改稿卡。

### 学生执行版

学生执行项不能只写“去改摘要”或“收紧讨论”，至少还要写明：

- 依据哪条方法学判断
- 具体修复动作是什么
- 改完后以什么为完成标准
- 是否还需导师/学生回查原始材料
- 当前属于 `L1 / L2 / L3 / L4` 的哪一层

### 导师分层建议

进入导师层后，默认先补一份 `导师分层修改建议.md`，按 [mentor-constructive-layers.md](./mentor-constructive-layers.md) 将建议分成 `L1-L4`，不要把不同工作量项目写成同一优先级。

### 语言校准表

进入导师层后，默认再补一份 `流调统计语言校准表.md`，至少写出：

- `epi_basis`
- `stats_basis`
- `claim_boundary`
- `mentor_action`

### 前沿升级

如果问题进入 `L4`，先按 [frontier-innovation-gates.md](./frontier-innovation-gates.md) 产出 `前沿知识简报` 与 `创新定位判断卡`，再决定哪些内容进入导师摘要、答辩口径或未来研究。

### 退回评审

凡是 `不可由写作修复` 的问题，都不要继续包装成润色任务。应明确写成：

- 当前 blocker 是什么
- 需要补什么材料
- 在材料未补前最多能做哪些安全降级

## 6. 常见映射

### 样本量或证据强度不够

- 优先修复类型：`强度降级` + `局限性补写` + `范围收紧`
- 禁止动作：补造 power analysis、把未显著写成确定性

### 行为指标不足以支撑机制结论

- 优先修复类型：`范围收紧` + `局限性补写`
- 禁止动作：把代理指标包装成直接机制证据

### 摘要句与表图不一致

- 优先修复类型：`证据重锚` + `图表/表格回归`
- 禁止动作：跳过表图直接润色摘要

### 对照不充分却做强疗效归因

- 优先修复类型：`强度降级` + `局限性补写`
- 禁止动作：继续写成“优效”或“证实疗效”

### 关键方法学论断由综述支撑

- 优先修复类型：`引文升级`
- 禁止动作：继续用二手转述当定案依据

### 随机、盲法、注册或伦理信息缺证据

- 优先修复类型：`不可由写作修复`
- 允许的最小动作：保守描述 + `待人工回查`
- 禁止动作：补造设计特征、批件或注册号
