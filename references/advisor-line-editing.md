# 导师式逐条改稿流程

当用户不只要“评审意见”，还要“能直接替换回论文里的安全改写”时，加载此文件。

这不是让系统整篇自由重写论文，而是用导师批注的工作方式，把问题拆成最小可执行修改单元。

## 1. 触发条件

以下任一条件满足时，进入导师式逐条改稿模式：

- 用户明确说“导师视角”“逐段改”“逐句改”“逐条修改建议”“可直接替换”
- 用户要求按摘要、结果、讨论、结论逐段提出修改动作
- `reviews/评审闭环与放行判断.md` 已明确 `can_enter_line_editing = yes`

以下情况只提高改稿优先级，不单独构成进入条件：

- 论文已进入送审、盲审、预答辩或正式答辩前精修阶段

## 2. 核心原则

1. **先诊断，后改写**
   没有定位和问题类型，就不要直接给改写。
2. **一条建议只做一件事**
   例如，只收紧因果语气，或只补局限性，或只统一术语，不把多个动作塞进一句。
3. **每条改写都绑证据**
   证据可以是表、图、统计量、方法设定、伦理材料、参考文献原文。
4. **缺证据时停笔**
   需要回查原始数据、代码、文献、批件时，写 `待人工回查`，不要代写事实。
5. **优先改高风险段**
   摘要、结果、讨论、结论、图题表题、答辩高风险段落优先于一般叙述段。
6. **未闭环时只允许局部改**
   如果完整评审尚未闭环，只能响应用户明确指定的局部段落，不得默认扩展成全文执行清单或最终送审判断。

## 3. 逐条修改卡片格式

每条卡片固定包含：

- `定位`
- `原句 / 原段`
- `问题类型`
- `修改目标`
- `证据锚点`
- `建议改写`
- `禁止改法`
- `是否需人工回查`

推荐问题类型：

- 结论过强
- 证据缺口
- 术语不稳
- 章节错位
- 图表口径不一致
- 引文不匹配
- 统计表述不严谨
- 局限性缺位

## 4. 段落级工作顺序

### 摘要

- 先对齐 `目的 -> 方法 -> 结果 -> 结论`
- 不把边缘结果写成明确优势
- 不在摘要里塞方法学辩护

### 方法

- 只写做了什么，不补造设计美化
- 未做的盲法、注册、预设结局不要代写

### 结果

- 每句结果都要对得上表或图
- 一个句子只报一个主要发现，必要时拆句

### 讨论

- 先解释本研究结果，再谈文献，再谈边界
- 机制推断必须明显弱于直接结果

### 结论

- 只收口当前证据能支撑的层级
- 观察性研究不写成确证性因果

## 5. DOCX / 终稿精修工作流

如果用户希望形成接近导师批注的成品，按这个顺序组织：

1. 先抽取带行号底稿
2. 先做 `P0 / P1` 诊断，并确认是否已有 `评审闭环与放行判断.md`
3. 再输出逐条修改卡片
4. 再按章节聚合成“可直接回填”的改写建议
5. 最后单独列 `待人工回查` 和 `禁改项`

如果需要和 `DOCX` 修订模式对齐，至少保证每条建议都能映射到：

- 某一节
- 某一段
- 某一句

## 6. 禁改红线

- 不补造数据、注册号、盲法、独立评估者、代码流程
- 不把探索性结果改成确证性结论
- 不把观察性比较改成“证明某药更优”
- 不把文献推测改成“本研究发现”
- 不为了一句通顺而改变统计意义和方向
