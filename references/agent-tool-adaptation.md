# 跨代理 / 跨开发工具适配

当任务不是只在单一环境里完成，而是需要综合 `Codex`、`Claude Code`、`AntiGrativity` 或其他终端型代理的输出时，加载此文件。目标不是为某一个工具单独写一套技能，而是让同一套论文审查方法在不同代理环境下保持证据标准、交付结构和风险边界一致。

## 1. 基本原则

- 技能的主逻辑保持不变，变化的是证据获取路径和工具能力边界。
- 不把某个代理的“分析结论”直接当事实；一切关键判断仍以原论文、原图表、原始交付物为准。
- 最终交付物面向用户，而不是面向代理；不要把某个平台特有的术语、命令习惯或内部状态写进正式报告。

## 2. 证据优先级

跨代理协作时，固定按下面顺序判断可信度：

1. 论文原文、原表格、原图片、原始项目文件
2. 从原文件直接导出的页面图、裁切图、文本抽取结果
3. 官方指南、期刊规范、方法学一手来源
4. 导师意见、外审意见、其他 AI 或代理的建议
5. 终端 transcript、截图、代理自述、二手摘要

只要上层证据和下层证据冲突，优先服从上层证据。

## 3. 不同代理环境的适配重点

### Codex

- 强项通常是：本地文件编辑、结构化交付物整理、脚本化检查、HTML 汇总页维护。
- 如果环境支持浏览器、截图、网页核对，应优先用来验证图片、指南和最新规范。
- 最终应把口头分析沉淀为稳定文件，而不是停留在对话里。

### Claude Code

- 强项通常是：终端探索、脚本执行、长链路分析、快速提出结构性建议。
- 如果 Claude Code 给出了新建议，把它视为“第三方建议复核输入”，不要直接跳过本地核查。
- 终端里的自我解释、过程思考和命令输出，不应原样进入正式交付物。

### AntiGrativity

- 常见价值是：对其他代理输出再做审稿式复核，指出遗漏、过度判断和技术回归。
- AntiGrativity 的判断应视作“复核意见”，适合进入 `Adopt / Adopt with rewrite / Downgrade / Reject` 流程。
- 如果它基于截图、terminal 摘要或转述做判断，仍需回到本地文件确认。

### 其他终端型代理

- 先识别它输出的是：原文事实、方法学判断、图表建议，还是纯 workflow 提议。
- 如果只是策略性意见，可进入 `Strategy` 或 `Upgrade`；如果声称发现了硬伤，必须本地复核后再升为 `P0/P1`。

## 4. 统一处理规则

无论来自哪个代理，统一这样处理：

1. 先标记来源：`原文核查 / 外审 / 导师 / Claude Code / AntiGrativity / 其他`
2. 再判断证据层级：它基于什么材料得出这个结论
3. 最后落到四类：`Adopt / Adopt with rewrite / Downgrade / Reject`

不要写成“某代理说了什么，所以成立”；要写成“经回查原文/图表后，该建议成立或不成立”。

## 5. 环境差异下的降级策略

如果当前代理环境缺少某类能力，不要硬装，按下面方式降级：

- 没有浏览器或图片预览：先导出页面渲染图、本地裁切图，再做图表审查；优先使用 `Word / WPS` 原生导出或受控网页渲染，必要时再退回 PDF 页图
- 不能联网：只做本地事实核查，并明确“最新规范未在线验证”
- 不能稳定编辑 HTML：先完成 Markdown 和清单，HTML 作为下一步
- 不能直接访问另一个代理的会话：把用户提供的 transcript、截图或总结当作二手输入处理

降级可以，但必须明确当前结论的证据边界。

## 6. 交付物统一要求

跨代理协作后，最终落地的文件结构、命名和层级应保持一致：

- 综合报告：负责完整论证
- 执行清单：负责优先级和动作
- HTML 汇总页：负责总览、导航和答辩准备
- 学生版 / 导师版：负责轻量分发

不要因为更换代理，就改变文件命名、层级定义或优先级体系。

## 7. 常见误区

- 把代理的“思考过程”当证据
- 把代理截图中的总结文字当成已经核实的事实
- 因为某个代理表达很强势，就把建议自动升为 `P0`
- 在正式交付物里保留 `Codex`、`Claude Code`、`AntiGrativity` 的平台语境或命令细节
- 不区分“硬伤修复”和“高回报增强”，导致被不同代理的建议带偏优先级

## 8. 适合直接复用的表述

- “以下建议来自其他代理或评审工具，均已按原文、图表和当前版本文件状态二次核查。”
- “代理输出可作为高价值线索，但不替代对论文原始证据的回查。”
- “若不同代理结论不一致，以原文、图表和一手规范为最终裁决依据。”
