# Display Projection Gates

当任务需要生成网页、HTML、多页展示层、可分享评审页、学生页或导师页时，加载此文件。

核心原则只有一句：

`display_projection` 不是内部工作过程的直出投影，而是面向特定读者的成品表达。

因此，生成网页前必须依次通过三道闸门：

1. `评审闭环与放行判断`
2. `audience_language_contract`
3. `display_projection_schema`

三道闸门都过了，才允许开始写页面。

## 1. 闸门 A：放行前提

先回答“这页现在有没有资格承载执行动作或最终判断”，再决定是否继续写页面。

在生成页面前，先看 `reviews/评审闭环与放行判断.md`，至少确认：

- `can_emit_problem_list`
- `can_emit_execution_outputs`
- `can_issue_readiness_verdict`

默认规则：

- 入口页、问题清单页、完整评审页可以在评审进行中先产出，但必须如实展示“评审进行中 / 暂不放行”
- 学生执行页、导师汇报页只有 `can_emit_execution_outputs = yes` 时才允许产出
- 任何页面上的“建议送审 / 建议答辩 / 当前可直接执行”都只有在相应字段明确放行时才允许写

如果 `can_issue_readiness_verdict = no`，入口页、完整评审页和导师汇报页都不得提前写成最终送审 / 答辩结论。

## 2. 闸门 B：受众语言合同

先回答“这页是写给谁看的”，再回答“这页怎么说”。

默认把网页受众分成五类：

1. 入口页读者
2. 问题清单页读者
3. 完整评审页读者
4. 学生执行页读者
5. 导师汇报页读者

在生成页面前，先写一份 `reviews/audience_language_contract.md`，至少包含：

- 页面名
- 目标读者
- 使用场景
- 允许的表述方式
- 禁止直接暴露的内部术语
- 风险等级怎么表达
- 页面首层应该保留什么判断

### 2.1 允许的语言

- 面向论文评审、修订、送审、答辩的正式中文
- 可以保留必要的英文研究术语、统计术语和文件名
- 可以保留 `P0 / P1 / P2 / P3 / P4`

### 2.2 禁止直接暴露的内部语言

以下内容默认不得直接进入页面可见文本，除非用户明确要求保留内部工作语言：

- `truth_source`
- `execution_object`
- `status_projection`
- `display_projection`
- `process_projection`
- `workflow layer`
- `registry layer`
- `drilldown`
- `gate`
- `工作台`
- `真源`
- `法证`
- `标绿`

如果这些概念在内部流程里确有必要，必须先翻译成受众语言后再展示。例如：

- `真源` → `正式依据` / `唯一依据`
- `gate` → `前置核查项` / `进入下一步的条件`
- `drilldown` → `详细说明`
- `工作台` → `网页入口页` / `评审页面`

### 2.3 句子级审校要求

不要只扫黑话词表。页面完成前，必须逐段检查：

- 标题是否像正式评审标题，而不是内部推进口号
- 按钮、badge、footer、modal 标题是否仍带内部工程词
- 句子是否存在口语化推进语气，例如“打成大修”“写过头”“卡死”“越修越乱”
- 结论句是否在替读者做专业判断，而不是暴露内部工作感受

如果一段话更像“团队工作记录”，而不是“面向学生、导师或评审者的正式页面”，就不能直接上屏。

## 3. 闸门 C：内容扩增合同

先回答“这页要帮助读者做什么判断”，再决定“页面上放什么模块”。

在生成页面前，先写一份 `reviews/display_projection_schema.md`，至少包含：

- 页面名
- 页面目标
- 目标读者要做出的判断
- 必须出现的内容块
- 不应出现的内容块
- 每个内容块的上游依据文件

### 3.1 默认四类子页的内容合同

#### 问题清单页

必须回答：

- 当前有哪些问题
- 每个问题在哪里
- 为什么重要
- 应如何处理

至少包含：

- 优先级矩阵
- 全量问题卡片
- 关键图表证据入口

不应承担：

- 完整 workflow 叙述
- 学生逐项执行分工
- 导师决策摘要

#### 完整评审页

必须回答：

- 当前评审推进到了哪里
- 整体问题结构是什么
- 审阅步骤推进到了哪里
- 各项核查做到了什么程度
- 下一步怎么推进

至少包含：

- 总体判断
- 当前评审状态；只有放行后才写 readiness 判断
- 审阅步骤
- 逐项核查结果
- 图表专项
- 剩余评审步骤或放行后的执行顺序
- 交稿前终检

#### 学生执行页

必须回答：

- 现在先改什么
- 顺序怎么排
- 每项做到什么算完成
- 哪些材料还需要人工补

至少包含：

- 当前动作清单
- 顺序
- 完成标准
- 待人工回查项
- 禁止事项

前提：

- `can_emit_execution_outputs = yes`

#### 导师汇报页

必须回答：

- 当前论文定位是什么
- 当前是否已经达到放行条件
- 最关键的高风险项是什么
- 当前保留什么主线
- 需要导师拍板什么

至少包含：

- 总体判断
- 关键风险
- 主线保留
- 关键决策点
- 答辩口径

前提：

- `can_emit_execution_outputs = yes`
- 只有 `can_issue_readiness_verdict = yes` 时才写是否建议送审 / 答辩

### 3.2 内容扩增停止规则

以下内容默认不算“内容扩增”，不要把它们误当成页面已经更完整：

- 只增加 tabs / accordion / modal / drilldown
- 只增加 tips
- 只增加流程图，但没有补充新的评审判断
- 只增加页面装饰或版块标题，没有补充逐项核查结果

真正的内容扩增，必须至少新增以下三类信息中的一种：

1. 新的评审判断
2. 新的逐项核查结果
3. 新的修订决策信息

## 4. 共享上游与同步要求

四个子页不能各写各的。默认至少共用四类上游：

1. 共享问题映射台账
2. `评审闭环与放行判断`
3. `audience_language_contract`
4. `display_projection_schema`

如果其中任一项变化，相关子页都要同步回查。

## 5. 失败信号

出现以下任一情况，说明页面还没过闸门：

- 页面里仍能直接看到内部工作语言
- 问题清单页和完整评审页几乎只差标题
- 学生页里堆满导师判断
- 导师页里堆满逐条执行细节
- 评审尚未放行，却已经出现“现在先改什么”或“建议送审 / 答辩”
- 页面扩了结构，却没有补“完整结果”
- 页面首层只剩流程机制，没有留下评审结论
