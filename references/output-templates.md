# 产出模板

当需要把论文审查结果落成具体交付物时，加载此文件。默认以中文交付为主；若原文是英文论文，也优先用中文给出判断和执行建议，除非用户明确要求英文版成品。

## 0. 先出证据型中间产物，再出总结材料

复杂或高风险论文，不要一上来只写综合报告。先产出并实填证据型中间文件，再汇总成最终交付物。

常用的证据型中间文件包括：

- `process_projection.md`
- `审阅对象冻结说明.md`
- `版本冻结与依赖回归台账.md`
- `关键数值与复算准入台账.md`
- `图表索引台账.md`
- `图表专项核查.md`
- `核心结果证据链表.md`
- `目标试验与因果识别审计表.md`
- `伦理合规与数据追溯审计表.md`
- `主文补充附录交叉索引台账.md`
- `文献对标与引文法证.md`
- `上下文隔离反思.md`

这些文件不要求每篇论文全开，但至少要覆盖本轮最主要的风险源。空模板、只写标题的骨架文件，不算“已完成审查”。

如果论文高度依赖图、表、引文或多线程接手，再补对象层真源：

- `objects/figures.json`
- `objects/tables.json`
- `objects/citations.json`
- `objects/assets_manifest.json`

这些对象文件不是展示页，也不是长文台账，而是供后续台账、HTML 和回归检查复用的结构化上游。

## 1. 标准交付组合

在证据型中间文件已有实填内容后，完整审查通常至少包含三份材料：

1. `论文多智能体审查报告.md` 或同等综合报告
2. `最终可执行修改清单.md` 或同等行动清单
3. `综合评审汇总.html` 或同等可视化汇总页

如果用户明确要求导师视角、原子级修改建议或可直接替换的文字版本，再补：

- `原子级修改建议.md`
- `论断-引文核查表.md`
- `证据绑定改写表.md`

如果论文进入“强制深审”模式，建议再固定补三份证据型材料，或将其合并为综合报告附录：

- `核心结局证据链表.md`
- `干预与对照矩阵.md`
- `图片法证核查.md`

如果 workflow 很复杂，或论文经历了多轮改稿、多代理协作、摘要结论反复漂移，再优先补以下治理型文件：

- `process_projection.md`
- `审阅对象冻结说明.md`
- `版本冻结与依赖回归台账.md`
- `关键数值与复算准入台账.md`
- `主文补充附录交叉索引台账.md`
- `伦理合规与数据追溯审计表.md`
- `文献对标与引文法证.md`

如果图表问题或答辩问题特别重，再补：

- `图片专项修改清单.md`
- `答辩口径.md`
- `第三方建议复核意见.md`

## 2. 建议同时拆出两份轻量材料

当完整版开始超过普通修改者的阅读负担时，建议同步拆出：

### A. 学生执行版

只保留：

- 当前必须改什么
- 顺序怎么排
- 每一项的完成标准

不要在学生版里堆过多背景论证。

### B. 导师摘要版

只保留：

- 论文当前定位
- `P0` 的数量和最关键几条
- 是否建议答辩 / 是否建议送审
- 最值得保留的主线
- 最该收紧的结论

导师版的目标不是“教学生怎么改”，而是让导师 1 分钟内知道决策重点。

## 3. 综合报告模板

建议结构：

### A. 总体判断

- 这篇论文现在能否答辩 / 送审？
- 最关键的 `3-5` 条理由是什么？

### B. 多镜头发现

只有在有帮助时才按镜头展开。常用镜头：

- 流行病学
- 统计学
- 学术写作
- 工程实现
- 康复科学
- 神经科学

每条发现尽量包含：

- 问题是什么
- 原文或图表定位
- 为什么有风险
- 建议怎么改
- 是否已确认 / 仍待核实

如果属于临床干预 / 康复工程深审，建议在综合报告中专设一节“证据链附录”，最少包括：

- 核心结局证据链表
- 干预与对照矩阵
- 工程可复现性矩阵
- 图片法证结论

### C. 共识结论

总结多镜头都指向了什么。这部分通常最能揭示真正的瓶颈。

## 4. 执行清单模板

固定按优先级结构写：

### `P0`

- 阻止安全送审或答辩的问题
- 每条都要写清楚到底要统一、补充、重算、还是收紧

### `P1`

- 高概率被追问、会明显拉低严谨度的问题

### `P2`

- 方法与报告规范加固

### `P3`

- 清稿、展示、术语、编号、格式与交付回归

### `P4`

- 外审 / 答辩防守增强，不造新事实

### `Strategy`

- 高回报答辩增强，不补造事实

### `Upgrade`

- 下一轮研究或投稿导向的结构升级

每条尽量按这个小结构写：

1. 问题
2. 为什么危险
3. 安全修法
4. 明确禁止做什么

对进入强制深审的论文，`P0` 部分优先按这几个源头归类，避免只写零散问题：

1. 研究身份与样本流程
2. 核心结局证据链
3. 干预与对照可信度
4. 图片语义与统计呈现

## 4.5 导师式原子改稿模板

当用户要的是“直接怎么改”，不要把完整版评审长文简单换个标题。至少输出一组原子修改卡片。

推荐卡片字段：

1. `定位`
2. `原句 / 原段`
3. `问题类型`
4. `修改目标`
5. `证据锚点`
6. `建议改写`
7. `禁止改法`
8. `是否需人工回查`

推荐问题类型：

- 结论过强
- 结果句不对表
- 统计表述不严谨
- 引文不匹配
- 术语不稳
- 章节错位
- 图题 / 表题不准确

如果用户要“可直接替换文本”，也必须保留 `证据锚点` 和 `禁止改法`，不要只给改写句。

对 `DOCX` 终稿精修，建议再补一个按章节汇总的版本：

- 摘要精修
- 方法精修
- 结果精修
- 讨论精修
- 结论精修

## 5. HTML 汇总页模板

HTML 的目标是：准、全、能跳转、能打印、能共享。对“强制深审”项目，HTML 默认不是简短概览，而是可直接给导师、学生和答辩准备使用的证据工作台。

先确认前置证据文件已经实填，再生成 HTML。不要让 HTML 代替尚未完成的图表核查、版本冻结或结果真源核实。

生成 HTML 前，先整理一份“问题映射台账”，至少包含：

- `问题 ID`
- `级别`
- `原文或图表定位`
- `证据路径`
- `为什么危险`
- `安全修法`
- `答辩追问点`
- `确认状态`

没有进入台账的问题，不要直接写进 HTML；未核实但必须提醒人工回查的点，统一标成 `待人工回查`。

如果图像和表格资产已经对象化，优先从 `objects/assets_manifest.json`、`objects/figures.json` 和 `objects/tables.json` 生成 HTML 中的证据路径、图号和 caption，不要在 HTML 里手写绝对路径。

建议版块：

1. 首页总览与结论
2. 优先级矩阵
3. 问题卡片
4. 图表专项
5. 答辩增益策略
6. 研究升级路线
7. 执行顺序
8. 交稿前终检

制作 HTML 时要注意：

- 锚点稳定，不要频繁改 `id`
- 数量指标要和正文同步
- 卡片可以紧凑，但不能牺牲证据映射；避免把大段背景论证原样塞进 HTML
- 图像问题直接给本地图证、页图或裁图，不要只放“入口”
- 非图像问题也要给原文定位、摘录或行号，不能只写抽象结论
- 终检模块必须存在，否则页面只是“诊断书”，不是“工作台”

问题卡片固定结构：

1. `问题 ID + 级别`
2. `定位映射`
3. `证据展示`
4. `为什么危险`
5. `安全修法`
6. `答辩追问点`
7. `确认状态`

覆盖规则：

- `P0 / P1 / P2` 每条都要有对应卡片
- 当问题总数 `<= 15` 时默认全部展开，不要只留摘要面板
- 当问题总数 `> 15` 时，至少 `P0 / P1` 全展开，`P2` 可折叠
- 图表问题必须展示关键缩略图证或页图
- 非图表问题必须能追溯到原文、表格、文件行号或其他本地证据
- 如果某条问题仍依赖学生回查原始记录，卡片里要明确写出“待人工回查什么”

如果属于强制深审项目，HTML 中至少要能看见：

- 深审触发原因
- 哪些问题由哪个 agent / 专家镜头确认
- 核心结局证据链摘要
- 图片法证摘要和关键缩略图证

生成完成后，至少补跑一次 HTML 交付回查：

- 首页统计、优先级矩阵、问题卡片数量是否和综合报告、清单一致
- 每张卡片是否都保留了 `定位映射 / 证据 / 为什么危险 / 安全修法 / 答辩追问点 / 确认状态`
- 所有锚点、图片路径、图号、表号、证据链接是否仍然有效
- 页面是否把任何 `P0` 弱化成了“建议优化”

如果图表问题是核心争议，记得同步加载 [figure-table-standards.md](./figure-table-standards.md)，把“图表是否选对类型”“图注是否完整”“论文图与答辩图是否分流”一并纳入检查。

## 6. 第三方建议 / 其他代理输出复核回复模板

当用户问“某个 reviewer / AI / 代理工具的建议对不对”时，用这个顺序：

1. 先给总判断：大体同意 / 部分同意 / 不同意
2. 再拆成：
   - 明确正确
   - 方向对但要改写
   - 过强、过度或不安全
   - 已经过时，因为当前版本已修复
3. 每个判断尽量回到原文、表格、图片或当前文件状态
4. 最后标清它应该归入：
   - `P0 / P1 / P2`
   - `Strategy`
   - `Upgrade`

如果建议来源是 `Codex`、`Claude Code`、`AntiGrativity` 或其他终端型代理，额外补一句：

- “以下判断已回查原文、图表和当前工作区文件，不把代理输出本身视为最终证据。”

如果过程跨了多个线程或工具，额外补一句：

- “本轮过程摘要已压入 `process_projection`；以下结论以当前真源和证据型中间文件为准，不以聊天顺序本身为准。”

如果输出进入导师式原子改稿模式，额外补一句：

- “以下改写建议均绑定到当前可见证据；需要原始数据、代码或批件才能安全落笔的句子，已单列为待人工回查。”

## 7. 答辩口径小模板

以下句式可作为安全起点，再根据论文实际情况改写。

### 开放标签局限

“由于干预形式差异明显，本研究未能实施受试者和治疗师盲法，因此应界定为开放标签研究。该设计可能提高主观结局的偏倚风险，后续研究应进一步补充独立评估者盲法或录像盲评方案。”

### 探索性机制结果

“影像学结果应理解为探索性机制线索，而非对疗效机制的确证性证明。”

### 靶点不完全闭合时的安全表述

“尽管部分结局更偏向整体吞咽表现而非纯粹口腔期金标准，但口腔运动功能评分与相关表面肌电指标仍提供了与靶点更贴近的支持性证据。”

### 强但安全的结论

“本研究结果提示该方案具有潜在临床优势，但仍需在更大样本、标准化评估和更严格盲法条件下进一步验证。”

## 8. 交稿前终检模板

把它放在清单或 HTML 的末尾。

### 一致性检查

- 摘要、方法、结果、表格、图注里的样本数是否统一？
- 所有等级资料是否都改成了匹配的数据呈现？
- 每个“见图 / 见表”是否都指向正确对象？
- 图号是否唯一？中英文图题是否同步？
- 表格、图形、正文是否讲的是同一套统计口径？

### 方法和合规检查

- 研究身份是否诚实写清：随机、开放标签、探索性、pilot 或其他？
- 伦理审批和知情同意是否放在了标准位置？
- 注册状态是否准确交代？

### 解释边界检查

- 机制宣称是否没有超过证据？
- 探索性结果是否被明确标成探索性？
- 未来研究建议是否和已完成工作分开？

### 项目卫生检查

- README、CHANGELOG、实际目录结构是否一致？
- HTML 图片路径、锚点、统计指标是否仍然有效？
- 是否存在复制残留、控制字符、死链、旧版本路径？

### 交付物自审

以上终检查的是论文和项目文件。如果需要同时验证审查报告本身的准确性（引用是否对、分级是否一致、多份交付物是否同步、红线是否守住），加载 [self-audit.md](./self-audit.md)。

## 9. 高回报增强项

在 `P0 / P1` 收口后再考虑这些：

- 闭环机制概念图
- 小样本个体配对图
- 关键通道 / 关键连接的视觉强化
- 更好的答辩叙事弧
- 一段明确指出研究真正贡献的话

当增强项涉及图表时，优先考虑：

- 小样本个体图替代纯柱状图
- 关键通道 / ROI 高亮
- 完整但简洁的图注与表注
- 论文图与答辩图分开准备

对以下增强项要谨慎：

- 新补相关性分析
- 新补影像差值图
- 跨研究效应量对比
- 跨实验定量桥接

只有在原始数据、方法和时间都支持时才做，不要为了“看起来高级”临时扩分析。
