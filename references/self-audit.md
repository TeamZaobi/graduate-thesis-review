# 交付物自审清单

当审查产出（综合报告、修改清单、HTML 汇总页、学生版、导师版）即将交付时，加载此文件做最后一轮自检。

这份清单查的不是论文，而是**我们自己的审查报告**。论文终检见 [output-templates.md](./output-templates.md) 第 8 节。

## 1. 引用准确性

报告里每次引用论文原文时，都可能引入误读。以下检查点用于回验：

- 报告中每一条"原文写了 X"，是否回到论文原文逐字核对过？
- 引用的数据（样本数、P 值、均值、标准差）和论文原文是否完全一致？
- 引用的图号、表号和论文实际图表是否对应？
- 有没有把论文 A 章节的内容误归到 B 章节？

如果引用了 PDF 页面或图片作为证据，确认引用路径仍然有效。

## 1.5 深审闸门执行情况

如果论文属于临床干预、康复工程、神经工程或用户明确要求深审，交付前补查：

- 是否明确判断过“要不要进入强制深审”
- 如果进入了，核心结局证据链、干预与对照矩阵、图片法证核查是否至少出现了两项以上
- 是否把深审触发条件和核心结论写进了综合报告或 HTML
- 有没有口头上说“做了深审”，实际仍只有普通快筛产物

## 2. 分级一致性

同一个问题在不同交付物中的 P 级别必须统一：

- 综合报告中标为 `P0` 的问题，在修改清单中也必须是 `P0`
- HTML 汇总页的优先级矩阵，是否和清单的分级完全对齐
- 没有出现"报告里是 P1，清单里升成了 P0"或反过来的情况
- `Strategy` 和 `Upgrade` 项没有被混进 `P0/P1`

快速方法：在综合报告中搜索所有 `P0`，逐条到修改清单和 HTML 中找到对应项，确认级别一致。

## 3. 交付物间同步

多份交付物之间的数字和结论必须对得上：

### HTML 与清单

- HTML 首页统计的 P0/P1/P2 数量，是否和清单中的实际条目数一致？
- HTML 中的问题卡片，是否完整覆盖了清单中的所有 `P0 / P1 / P2`？
- HTML 锚点和卡片 ID 是否仍然有效、没有死链？

### HTML 细度与映射完整性

- 每张问题卡片是否都保留了 `定位映射 / 证据 / 为什么危险 / 安全修法 / 答辩追问点 / 确认状态`？
- 图表问题是否直接展示了关键页图、裁图或缩略图证，而不是只给文字结论？
- 非图表问题是否至少给出了原文定位、摘录、表格位置或文件行号？
- 如果总问题数 `<= 15`，HTML 是否已把全部问题展开，而不是只保留面板摘要？
- 标记为 `待人工回查` 的项目，是否明确写清楚了要回查什么原始记录？

### 学生版与完整版

- 学生版是否包含了**所有** P0 项？P0 不允许被精简掉
- 学生版中删去的内容，是否都确实属于 Strategy/Upgrade 或背景论证？
- 学生版中保留的动作项，措辞是否和完整版一致（不能改到含义不同）

### 导师版与综合报告

- 导师版的总体判断（是否建议答辩/送审）和综合报告的结论是否一致？
- 导师版列出的"最关键几条"是否确实是综合报告里级别最高的问题？
- 导师版对研究定位的表述是否和综合报告第四部分吻合？

## 4. 红线回检

Skill 在 SKILL.md 第 5 步定义了硬红线。交付前回检一次：

- 输出中有没有补造独立评估者、注册号、算法细节？
- 有没有把事后解释写成事前预设？
- 有没有把探索性结果的表述升格为确证性证明？
- "安全改写"建议中，有没有偷偷引入了原文中不存在的量纲或单位？
- 答辩口径中，有没有超出论文实际数据的机制宣称？

快速方法：全文搜索"证实""证明""确认""恢复""重建"等强因果词，逐个判断是否有证据支撑。

## 5. 内部一致性

审查报告自身不能自相矛盾：

- 多镜头之间有没有互相打架的判断？
  - 例如：统计学镜头说"应改用非参数"，但修改清单只写"补充效应量"
  - 例如：康复镜头说"靶点不闭合"，但答辩口径没有覆盖这个问题
- 总评的结论和分项发现是否一致？
  - 不能分项镜头都说"有严重问题"，总评却说"整体较好"
- 修改建议之间有没有冲突？
  - 一处建议保留某段落，另一处建议删除同一段落

## 6. 统计风险检查点

以下是从审查实践中沉淀的高频统计风险规则。当审查报告涉及统计方法的判断时，逐条核对：

### 数据类型与检验方法

- [ ] 等级资料（如洼田、FOIS、Brunnstrom）是否使用了非参数检验？如果仍用 t 检验 → P0
- [ ] 连续但明显非正态的数据，是否至少做了正态性检验或用了非参数方法？
- [ ] 重复测量数据是否用了重复测量方差分析或 GEE，而不是多次独立 t 检验？

### 多重比较

- [ ] 多通道/多 ROI 的 fNIRS/EEG 分析是否做了 FDR 或 Bonferroni 校正？如果只用 P<0.05 → 至少 P1
- [ ] 功能连接的两两 ROI 比较是否做了校正？
- [ ] 多个结局指标是否定义了主要/次要层级？如果全部同等报告 → 至少 P1

### 结论边界

- [ ] P 值处于 0.05–0.10 的边缘结果，报告中是否如实标注为"未达显著"？
- [ ] 未达显著的结局是否在摘要和结论中被弱化或省略，而非被强结论覆盖？
- [ ] 效应量和 95% CI 是否至少对主要结局有报告？

### 分析集

- [ ] 是否说明了 ITT 还是 PP 分析？
- [ ] 脱落数据是否交代了处理方式？
- [ ] 样本量估算依据是否合理、来源是否交代？

这些检查点同时服务于两个目的：审查论文时用它发现问题，审查报告交付前用它确认自己没有漏判。

## 7. 专家分工一致性

如果使用了专门 agent 或专家镜头，补查：

- `epi / stats / figure / engineering / writing / defense` 的结论有没有互相打架
- `stats` 说是核心结局硬伤的点，`defense` 是否已经准备回答
- `figure` 发现的图像语义问题，是否已经回写到 `P0 / P1`
- `engineering` 发现的方法透明度缺口，是否没有被“写作润色”掩盖

## 何时跑这份清单

- 当综合报告、修改清单、HTML 汇总页全部完成后
- 当学生版和导师版拆分完成后
- 当任何交付物被二次修改后（回归自审）

每次只需要花 5-10 分钟过一遍，重点不是每一条都重新核对，而是**快速扫描最容易出错的接缝**：引用数据、分级标签、HTML 数字、HTML 映射字段、学生版 P0 覆盖、红线词汇。
