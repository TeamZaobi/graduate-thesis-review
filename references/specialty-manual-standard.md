# 专项手册高标准规范

这份文件不负责路由单篇论文，而是定义：一份“可长期复用的专业专项手册”至少要长成什么样，才配得上进入共享 `references/`。

目标不是把每个专业都写成百科，而是把它们提升到“足以稳定支持毕业论文审查”的标准。

## 1. 先分清三种东西

不要把下面三类对象混成一类：

1. 共享专项手册：放在 `references/specialty-*.md`，跨论文复用
2. 本论文专项补充：放在 `notes/专业专项补充说明.md`，只服务当前论文
3. 院校/学院流程规则：属于“毕业论文场景层”，不是某个专业的领域规范

共享专项手册只负责“专业方法学与该专业常见毕业论文风险”，不应吃掉一切。

## 2. 一份共享专项手册的最低结构

每份手册头部必须写清：

```markdown
# [专业领域]专项

最后更新：YYYY-MM
适用范围：[具体专业 + 亚专业]
主要参考规范：[指南名称、版本年份]
```

正文至少要包含以下章节：

```markdown
## 触发条件
## 适用边界
## 研究类型分流
## 毕业论文场景重点
## 该领域特有的方法学要求
## 核心结局指标与金标准
## 学科语域与常用审查用语
## 报告规范要点
## 高频风险点
## 安全定位建议
## 屏蔽说明
## 与通用框架/其他专项的优先级
## 何时判定为手册不完备
```

缺少其中任一块，都不应视为高标准共享手册。

## 3. 每个章节至少要回答什么

### `## 触发条件`

- 哪些关键词、疾病、干预、测量或学院背景会触发
- 触发后通常与哪些其他专项共用

### `## 适用边界`

- 这份手册到底覆盖哪些亚专业、哪些病种、哪些研究语境
- 明确写出“不覆盖什么”

### `## 研究类型分流`

- 至少分别说明：本专业下 `RCT / 观察性 / 诊断 / 预测 / 纯工程` 哪些常见
- 每类论文优先查什么，不要只说“按通用框架处理”

### `## 毕业论文场景重点`

- 开题最容易被问什么
- 送审前最容易暴露什么
- 外审回复要怎么用这份手册
- 预答辩和正式答辩前，哪些问题必须前移

### `## 该领域特有的方法学要求`

- 只写本专业真正独特、会影响判断的 gate
- 不要把所有通用审查规则重复抄一遍

### `## 核心结局指标与金标准`

- 本专业常见核心结局
- 哪些是金标准，哪些只是替代指标、支持性指标或探索性指标
- 需要时补最常见的测量误区

### `## 学科语域与常用审查用语`

- 该学科导师、学生和外审最自然接受的审查用语是什么
- 哪些词属于跨学科行话，进入对外交付物会显得不专业
- 至少给出一组“推荐用语 / 不推荐用语 / 建议替换”
- 文件名、页面标题和问题标签如需直接给学生或导师看，也应遵守这套语域

### `## 报告规范要点`

- 该专业最常用的正式规范、扩展版或关键检查点
- 只列会影响论文把关的内容，不做大而全罗列

### `## 高频风险点`

- 最好按 `P0 / P1 / P2` 组织
- 每一类都应是“真实审查会命中的高频问题”，不是空泛提醒

### `## 安全定位建议`

- 小样本、探索性、替代终点、短随访、单中心等情形下，如何安全表述

### `## 屏蔽说明`

- 激活此专项时，哪些通用检查或相邻专项的默认标准要降权或屏蔽
- 原因是什么

### `## 与通用框架/其他专项的优先级`

- 这份手册和 `clinical-study-types.md`、`review-rubric.md` 的关系
- 和其他专项同时加载时，冲突点谁优先

### `## 何时判定为手册不完备`

- 哪些论文特征说明这份手册虽然存在，但还不足以支撑当前论文
- 何时应该转入 `paper-specific supplement`

## 4. 高标准不是写得长，而是写得可执行

一份高标准手册至少要做到：

- 能帮助判断 `P0 / P1 / P2`
- 能帮助判断“送审/答辩前还差什么”
- 能帮助回答“这篇论文哪里不该套通用模板”
- 能帮助后续代理或脚本稳定复用

如果只是经验随笔、概念提示或某篇论文的回忆录，不算合格共享手册。

## 5. 允许保留在本论文补充里的内容

以下内容默认不直接进入共享专项：

- 某一学校的摘要格式、致谢格式、图号格式
- 某一导师的偏好口径
- 某篇论文特有的仪器型号细节
- 某病种或某治疗亚型的单点经验，尚未明确可复用边界

这些内容应先停留在本论文补充或场景层文件里。

## 6. 新增或升级共享专项时的标准流程

1. 先走 `specialty-manual-readiness-gate.md`
2. 判为 `partial / missing` 后，先写本论文专项补充
3. 只有确认可复用，再新建或升级共享专项
4. 共享专项写完后，运行 `scripts/check_specialty_manual.py`
5. 最少补两类回归样例：
   - 命中该专项的正常场景
   - 手册仍然不完备、需要补充的边界场景

## 7. 推荐的证据来源顺序

新增或升级共享专项时，优先顺序应是：

1. 官方指南、正式 statement、领域规范
2. 报告规范扩展版或方法学一手来源
3. 近年高质量综述，用于补充争议点
4. 既往论文审查积累，但只能作为经验校验，不能单独做规范依据

不要只凭历史项目经验就新建共享专项。

## 8. 验收清单

一份专项手册准备进入共享层前，至少自问：

- 这个专业边界讲清楚了吗
- 相邻专业会不会被误伤
- 研究类型分流写清了吗
- 毕业论文阶段重点写清了吗
- 核心结局和金标准够用了么
- 学科语域和替换词够用了么
- `P0 / P1 / P2` 足够具体么
- 安全降级词能直接拿来用么
- 冲突优先级说清了吗
- 何时判为不完备写清了吗
- 已补 eval 了吗

只要其中几项答不上来，就说明还没到“高标准共享专项”的程度。
